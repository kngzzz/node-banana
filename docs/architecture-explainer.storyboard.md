# node-banana — storyboard

Commit `8929b7a` (package.json 2.1.0). 7 chapters (6 + recap), 149 s. Facts: `facts/node-banana.json`, checked against the source.
Layout: a 4-unit grid where the Run path is a staircase that reads left to right on screen, every pipe on an iso axis:
user → workflow canvas → workflow store → node executors → `/api/generate` → provider adapters → outside AI APIs.
The save branch hangs below it (executors → asset recorder → asset library), the workflow file sits above the store,
and the agent chat sits up-left, wired to the store (graph ops) and to the user (the Run card). The user's Run-card press
reaches the store on its own overhead pipe (user → store, drawn in decision 3), never through the agent block.
"another website" appears only in decision 1 and lifts away after it.

## Left out or simplified

- The flow is the facts' Gemini image node (`nanoBanana`, the default `gemini` provider), which answers in one request. Kie.ai and Comfy Router return a polling envelope and finish through `/api/generate/poll` (Comfy Router's ElevenLabs models are the exception and answer in one request, `route.ts:404-406`); that path is not drawn.
- `runBatch` runs up to `runCount` times and a failed run stops it early (the step says so); one run is drawn. Levels are named, but how they run in parallel (`maxConcurrentCalls`), pause edges ("Run resumes from a pause"), locked groups and the Stop button are left out.
- The executors rack shows 7 of the 11 executor files and the providers rack shows the 8 adapter files; grouping them as racks, and drawing the user as a module, is the fact sheet's own classification. `executeNode.ts` (built, unused) is left out.
- The outside AI APIs carry the Gemini adapter's path (`providers/gemini.ts`, which imports the Gemini SDK) because an outside service has no folder of its own; its owns line lists all seven services.
- The asset library is one cylinder for the media files, the sidecars (the truth), the journal, the run snapshots and the server code that indexes them; the server-side ingest (upload tickets in memory, `.partial` files) is folded into "a ticket, the bytes, then file, sidecar and journal". Run snapshots (`beginRun` / `endRun`) and the "sidecars are the truth; the journal informs" decision are not drawn on their own. An output that is an http(s) URL is downloaded by the server instead of uploaded (`recorder.ts:346`, `ingest.ts:177-179`); only the upload is drawn.
- The workflow file is drawn as a store on the store's own pipe; the `/api/workflow` route (`POST`) is part of it. Autosave timing, project folders and `/api/save-generation` (the fallback when the library is off) are left out.
- Crash: the whole web app is shown going down (tab and server), so the restart is a server start, when the library runs its once-per-process scan and sweep (`index.ts:287-299`; it also rescans when the journal is replaced or shrinks, or when it has fallen too far behind, `library.ts:692-699`, and sweeps project folders on first use, `ingest.ts:271-275`, neither drawn). A tab reload alone (server still up, index kept) is not drawn. Upload tickets lost with the server, the partly durable journal and run snapshots, and the inferred items (the Gemini call is not cancelled on abort, a Kie/Comfy task id lives only in the poll loop, power-loss risk for unsynced files, localStorage surviving) are left out. The store coming back from the saved file is a packet from the file to the store with a "web: back from a saved file" tag; who opens it (the user) is not drawn. Desktop recovery (Electron only; a Restore or Discard dialog, so the tag says "offers checkpoint") is shown by tags on the store and executors and a broken executors → `/api/generate` link; the checkpoint file (`checkpoint-v1.json`, written by Electron) is not a module.
- Decision 1 merges two facts-sheet decisions, "Keys travel with each request" and "The server answers only this machine" (README's "Local … BYOK"); only the cross-site refusal is drawn, not the loopback bind (shown as a tag in chapter 1). The step's "this machine" is that default: `HOST` can open the server to the network (`server.js:17-20`). "another website" is a temporary actor taken from the `server.js:59-61` comment. Other decisions left out: sidecars vs journal, agent turns only on a subscription, file and library routes check the caller, Run resumes from a pause, desktop recovery never resubmits (shown in chapter 4 instead).
- The agent is one block for the panel, the `/api/agent/chat` route, the harness and the tools. The Run card is offered on the agent → user pipe; the press goes user → store directly (`runs.ts:150`): its click handler sits in the chat panel (`AgentRunCard.tsx:216`, `:281`), but no agent turn, route or tool takes part, so the pipe skips the block. `view_outputs` reading the library, the canvas snapshot sent with each message, attachments, tabs, prompting guides and sign-in are left out.
- The library → canvas edge (carousels reload media by `assetId`) is not drawn.
- Left out entirely: ComfyUI app nodes and `src/lib/comfy`, the LLM route, the model catalog and browse dialog, library background jobs and thumbnails, logs and cost tracking, the Electron shell internals and updater (only the `electron/` tree row), `docs/`. The tree drops `src/app/api/workflow/` (the `src/app/api/` row lights the workflow file), `src/app/api/agent/`, `src/app/page.tsx`, `src/store/utils/`, `src/lib/providers/`, `src/lib/comfy/` and `src/types/` as rows of their own (the parent rows' notes cover some) to give each row 1.3 s.
